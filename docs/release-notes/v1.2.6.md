Windows support for the native backend. Until now `--install` stopped with `TODO: implement support for installing on "windows"`, so neither Chrome nor Firefox could find the backend there.

```
go run github.com/iazat/ts-browser-ext@latest --install=C<your-extension-id>   # Chrome
go run github.com/iazat/ts-browser-ext@latest --install=F                      # Firefox
```

On Windows, run it from an ordinary (not Administrator) PowerShell: the registration goes under `HKEY_CURRENT_USER`, and an elevated shell may belong to another account.

## Installing on Windows

The backend is copied to `%LOCALAPPDATA%\tailscale-browser-ext\NativeMessagingHosts\ts-browser-ext.exe`, the manifest is written beside it, and a key under `HKCU\Software\Google\Chrome\NativeMessagingHosts` or `HKCU\Software\Mozilla\NativeMessagingHosts` points the browser at the manifest. No admin rights are needed. `--uninstall` removes the keys as well as the files.

Windows will not overwrite a program that is running, and the browser keeps the backend running, so a reinstall renames the running `ts-browser-ext.exe` aside and the next install deletes it.

This path is built and unit-tested in CI but has not yet been run against a real browser on Windows.

## Also

- The native messaging manifest is now marshaled as JSON rather than formatted as text. A Windows path is full of backslashes, and pasting one between quotes produced a manifest the browser would reject.
