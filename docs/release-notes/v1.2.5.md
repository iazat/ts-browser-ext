The follow-up to v1.2.4: coming back on its own after the machine sleeps, and remembering the switch. Ported from #15 onto the v1.2.4 code. **Reload the extension after upgrading** — both manifests gained the `alarms` and `idle` permissions, and a worker running the old manifest cannot use them.

```
go run github.com/iazat/ts-browser-ext@latest --install=C<your-extension-id>   # Chrome
go run github.com/iazat/ts-browser-ext@latest --install=F                      # Firefox
```

## Coming back after the machine sleeps

Sleep takes the whole chain down: the browser suspends, the service worker is discarded, and the native host — its child process, holding the messaging port — dies with it. v1.2.4 reconnects with a backoff timer, but a timer set by the worker dies with the worker. What was left was waiting for someone to open the popup.

The retry is now also held by the browser, which starts the worker again to deliver it: a one-minute alarm, and the idle state flipping back to active, which is the earliest word that someone is about to load a page. Opening the popup reconnects at once too, rather than sitting out whatever backoff had built up. Each does nothing while a port is open, so a healthy backend costs nothing.

## A restart switched the tailnet back on

tsnet starts the backend with WantRunning set, whatever it was left at — the same replacement of preferences that reset the exit node in v1.2.4 — and the extension routed the browser through the new backend on sight. A profile switched off came back on at every browser start.

The backend now remembers the switch beside its state, as it does the exit node, and restores it right after start, before the IPN bus watcher subscribes. The extension no longer routes on `procRunning`: the backend's first status decides, and `State: Stopped` means direct browsing. The exceptions are a user who has asked for it and a browser that was going through the host that just died — that one is taken back the moment the replacement has a port, since every second on a direct connection with an exit node configured is traffic leaving from this machine's own address.

The toggle sends the state of the switch the user just operated, rather than the background inverting a variable a fresh worker had just lost; and a click made while the backend is away is remembered and delivered — after `init` — to the one that arrives.

## The popup spent the wait blank

Opening the panel after a wake means a new backend starting Tailscale from cold. The background keeps the last status in extension storage, and the popup paints it at once, under a spinner, until the background confirms or corrects it. An install command or a live answer that arrives first is never painted over.

## Also

- `chrome.storage.local.get` can answer nothing at all when the browser is tearing the worker down around the call. Reading a field off that threw, and the init the backend needs went with it. A refusal is retried, and never answered by inventing a profile id — which would be a new machine on the tailnet.
- A profile that has seen a backend before says "Reconnecting…" on a fresh worker rather than asking for an install, and only falls back to the install command once reconnects keep failing.
- Statuses that repeat the last one are not sent to the extension, and the toolbar icon is only redrawn when it changes. A tailnet of any size is never quiet, and each repeat was a redraw of the button being clicked.
- The dead-watch marker no longer overwrites `State: Stopped` or the login state, which the extension now reads to decide where traffic goes.
- Several popups open at once — the panel and `popup.html` in a tab — are all kept up to date.

## Known limitations

- **Firefox has still not been run live.** The `firefox/` copy carries every change here and passes the same suites.
- **Windows cannot register the native host.** The binary builds, but there is no registry install path yet.
